# Requirements Traceability & Gap Analysis — Dhaka Tesla Pool

**Purpose:** answer two questions for every brief requirement: _"Where is this documented?"_ and _"How will it be tested?"_ This file also hosts the **assumptions register** and **open decisions**, because both are cross-document audit artifacts (justification for this file: see §0).

> ⚠️ **Assumption A-00 (read first):** the original brief document was **not present in the repository or anywhere searched on this machine**. This matrix therefore maps the _brief requirements as restated in the two master prompts_ (the prompting instructions). Before implementation starts, this table must be re-validated line-by-line against the actual brief file — any row that cannot be found in the real brief should be challenged, and any brief line missing here must be added.

## 0. Why a separate file

1. **Required by the stage:** this stage must produce a traceability matrix + gap analysis covering _all_ documents — embedding it in `requirements.md` would bloat a spec whose job is to specify the system, not audit the docs.
2. **Cross-cutting:** rows reference PRD ↔ requirements ↔ architecture ↔ DB ↔ API ↔ UI ↔ tests ↔ todo — a single home avoids circular cross-references.
3. **Audit lifecycle:** after your human review, the next stage is a _documentation audit_; keeping findings, assumptions, and open decisions together makes that pass mechanical.

## 5. Git workflow (required conventions)

**Branches:** `main` (always deployable; brief calls this `master` — D-03) · `pre-release` (stabilization/QA integration) · `release/v1.0.0` (cut for a version; hotfixes only) · `feature/<slug>` (e.g., `feature/passenger-auth`, `feature/tesla-pooling`, `feature/driver-flow`).

```text
feature/passenger-auth ──PR──► main ──► pre-release ──► release/v1.0.0 ──► tag v1.0.0
                                    ▲        └──── hotfixes back-merged ────┘
```

**Commit format:** `<type>(<scope>): <short description>` with `type ∈ {feat, fix, refactor, test, docs, chore, build}`.

Examples: `feat(pool): enforce capacity with atomic seat claim` · `fix(rides): reject cancel after STARTED` · `test(concurrency): add 100-run last-seat race` · `docs(api): document idempotent POST /rides` · `chore(docker): add healthchecks to compose`.

**Rules:** no meaningless commits created merely to tick a requirement box — every task earns at least one purposeful commit; secrets never enter history; noisy WIP is squashed at merge; the Phase 15 DoD audits compliance.
